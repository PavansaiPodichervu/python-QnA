# 1. What Is a RAG Evaluation Dataset?

## Definition

A **RAG evaluation dataset** is a collection of test questions and expected answers, along with supporting information used to evaluate a Retrieval-Augmented Generation application.

It helps measure whether a RAG application:

- Retrieves relevant documents.
- Retrieves sufficient information.
- Generates relevant answers.
- Produces answers supported by retrieved context.
- Correctly answers user questions.

### Example

Suppose you are developing an HR chatbot.

You have 100 HR documents:

- Leave policies
- Salary policies
- Employee benefits
- Insurance policies
- Attendance policies

You need to determine whether the chatbot answers questions correctly.

Instead of manually testing random questions every time, you create a dataset.

| Question | Reference Answer |
|---|---|
| How many annual vacation days are available? | Employees receive 20 vacation days. |
| What is the sick leave allowance? | Employees receive 10 sick leave days. |
| What is the insurance coverage? | Employees receive insurance coverage of ₹5 lakh. |

This dataset becomes your evaluation benchmark.

---

# 2. Why Evaluation Datasets Are Important

Without a dataset, you cannot reliably determine whether your RAG application is improving or degrading.

Consider two versions of your application.

| Version | Context Precision | Context Recall | Faithfulness |
|---|---:|---:|---:|
| Version A | 0.65 | 0.70 | 0.75 |
| Version B | 0.88 | 0.91 | 0.95 |

Version B appears better across these metrics.

But how did you calculate these scores?

You need test questions, references, retrieved contexts, and generated answers.

These come from your evaluation dataset and evaluation pipeline.

### Evaluation Dataset Benefits

- Regression testing
- Retrieval optimization
- Prompt optimization
- Model comparison
- Embedding model comparison
- Chunking strategy comparison
- Production quality monitoring

# 3. RAG Evaluation Dataset Schema

A typical RAG evaluation dataset contains the following fields.

| Field | Description |
|---|---|
| user_input | Original user question |
| reference | Expected correct answer |
| retrieved_contexts | Documents retrieved by the RAG system |
| response | Answer generated by the RAG system |

Some evaluation metrics require additional fields or different inputs.

## Example Record

```python
sample = {
    "user_input": (
        "How many annual vacation days do employees receive?"
    ),

    "reference": (
        "Employees receive 20 annual vacation days."
    ),

    "retrieved_contexts": [
        "Employees receive 20 annual vacation days.",
        "Employees receive 10 sick leave days."
    ],

    "response": (
        "Employees receive 20 annual vacation days."
    )
}
```

### Understanding the Fields

**user_input**

The question asked by the user.

**reference**

The expected correct answer.

**retrieved_contexts**

The actual documents retrieved by your RAG application.

**response**

The answer generated by your RAG application.

### Important

Do not confuse the reference answer with the generated answer.

The reference is created or verified independently.

The response is produced by your RAG application.

# 4. Evaluation Dataset vs Training Dataset

These datasets serve different purposes.

| Dataset | Purpose |
|---|---|
| Training dataset | Train or fine-tune a model |
| Evaluation dataset | Measure model or application performance |
| Validation dataset | Tune model or application configuration |

A RAG evaluation dataset is generally not used to train the LLM directly.

It is used to evaluate the RAG application.

### Example

You change:

- Chunk size
- Embedding model
- Retriever
- Reranker
- Prompt
- LLM

You can reuse the same evaluation dataset to compare versions.

This makes comparisons more reliable.

# 5. Creating Questions From Documents

The first step is generating realistic questions from your knowledge base.

Suppose you have this document:

```text
Employee Vacation Policy

Employees receive 20 annual vacation days.

Employees can carry forward up to 5 unused vacation days.

Vacation requests require manager approval.

Vacation requests should be submitted at least 3 days in advance.
```

You can create questions from it.

| Document Information | Evaluation Question |
|---|---|
| 20 annual vacation days | How many annual vacation days do employees receive? |
| Carry forward 5 days | How many unused vacation days can employees carry forward? |
| Manager approval | Who approves vacation requests? |
| Submit 3 days in advance | How early should vacation requests be submitted? |

These questions test whether the retriever and generator can use the document correctly.

## Question Types

Create different types of questions.

### Type 1 — Direct Questions

```text
How many annual vacation days do employees receive?
```

### Type 2 — Multi-Fact Questions

```text
How many vacation days are available and how many can be carried forward?
```

### Type 3 — Conditional Questions

```text
Can employees carry forward unused vacation days?
```

### Type 4 — Comparison Questions

```text
What is the difference between vacation leave and sick leave?
```

### Type 5 — Multi-Document Questions

```text
What are the vacation allowance and manager approval requirements?
```

### Type 6 — Unanswerable Questions

```text
Does the company provide unlimited vacation?
```

If the knowledge base does not contain this information, the system should avoid inventing an answer.

Include unanswerable questions to test abstention behavior.

# 6. Generating Ground Truth

Ground truth is the expected correct answer for an evaluation question.

## Example

Question:

```text
How many annual vacation days do employees receive?
```

Reference:

```text
Employees receive 20 annual vacation days.
```

The reference answer should be:

- Correct
- Clear
- Supported by the source
- Sufficient to answer the question
- Independent of the model's generated response

## Ground Truth Generation Approaches

### Approach 1 — Manual

A domain expert reads the document and writes questions and answers.

Advantages:

- High quality
- Reliable
- Suitable for critical applications

Disadvantages:

- Time-consuming
- Expensive for large datasets

### Approach 2 — LLM-Based Generation

An LLM generates questions and answers from documents.

Advantages:

- Fast
- Scalable
- Useful for large document collections

Disadvantages:

- Generated questions may be trivial
- References may contain incorrect information
- Questions may not represent actual users

### Approach 3 — Hybrid

Use an LLM to generate questions and answers.

Then review and validate them manually.

This is often a practical approach.

# 7. Synthetic Evaluation Dataset Generation

Synthetic dataset generation means creating evaluation examples using an LLM instead of manually writing every question.

## Workflow

```text
Source Documents
      |
      v
LLM Question Generation
      |
      v
LLM Reference Answer Generation
      |
      v
Dataset Validation
      |
      v
Human Review
      |
      v
Evaluation Dataset
```

## Example Prompt

```text
You are generating evaluation questions for a RAG application.

Read the document below.

Generate:
1. Five realistic user questions.
2. A correct reference answer for each question.
3. The exact supporting information from the document.
4. One multi-fact question.
5. One unanswerable question.

Do not invent information.

Document:
{document}
```

### Important

Generated questions should be reviewed.

Do not blindly trust synthetic references.

# 8. Python Implementation — Create Dataset

We will create a simple evaluation dataset using Python.

## Step 1 — Define Documents

```python
documents = [
    """
    Employee Vacation Policy.

    Employees receive 20 annual vacation days.

    Employees can carry forward up to 5 unused vacation days.

    Vacation requests require manager approval.
    """,

    """
    Employee Sick Leave Policy.

    Employees receive 10 sick leave days annually.

    Sick leave can be used for medical reasons.
    """
]
```

## Step 2 — Define Evaluation Questions

```python
evaluation_questions = [
    {
        "question": (
            "How many annual vacation days do employees receive?"
        ),

        "reference": (
            "Employees receive 20 annual vacation days."
        )
    },

    {
        "question": (
            "How many vacation days can employees carry forward?"
        ),

        "reference": (
            "Employees can carry forward up to "
            "5 unused vacation days."
        )
    },

    {
        "question": (
            "How many sick leave days are available annually?"
        ),

        "reference": (
            "Employees receive 10 sick leave days annually."
        )
    }
]
```

## Step 3 — Create Dataset Records

```python
dataset = []

for item in evaluation_questions:

    record = {
        "user_input": item["question"],
        "reference": item["reference"]
    }

    dataset.append(record)

print(dataset)
```

Output:

```text
[
    {
        'user_input':
        'How many annual vacation days do employees receive?',

        'reference':
        'Employees receive 20 annual vacation days.'
    },

    ...
]
```

## Step 4 — Save Dataset as JSON

```python
import json

with open(
    "rag_evaluation_dataset.json",
    "w",
    encoding="utf-8"
) as file:

    json.dump(
        dataset,
        file,
        indent=4,
        ensure_ascii=False
    )
```

This creates:

```text
rag_evaluation_dataset.json
```

You can reuse this dataset later.

# 10. Dataset Quality Validation

A poor evaluation dataset produces unreliable evaluation results.

## Quality Rule 1 — Reference Accuracy

Every reference answer should be supported by the source documents.

## Quality Rule 2 — Question Diversity

Include:

- Simple questions
- Multi-fact questions
- Complex questions
- Comparison questions
- Unanswerable questions

## Quality Rule 3 — Avoid Duplicate Questions

Example duplicates:

```text
How many vacation days are available?

What is the annual vacation allowance?
```

These may test nearly the same information.

Duplicates can distort evaluation.

## Quality Rule 4 — Avoid Trivial Questions Only

A dataset containing only simple questions may make your RAG application appear better than it is.

## Quality Rule 5 — Include Difficult Questions

Examples:

```text
What is the vacation allowance and carry-forward policy?

What happens when an employee submits a vacation request late?

Can employees carry forward more than five unused vacation days?
```

## Quality Rule 6 — Include Unanswerable Questions

Example:

```text
Does the company provide unlimited vacation?
```

If the knowledge base does not contain this information, the application should acknowledge the limitation.

## Quality Rule 7 — Review Synthetic Data

LLM-generated questions and references must be checked for:

- Hallucinations
- Incorrect answers
- Missing facts
- Ambiguous wording
- Unsupported assumptions

# 11. Preparing a Dataset for RAGAS

RAGAS supports evaluation datasets containing question-answer and retrieval-generation information.

## Example Using RAGAS Dataset

```python
from ragas import EvaluationDataset, SingleTurnSample

samples = [
    SingleTurnSample(
        user_input=(
            "How many annual vacation days "
            "do employees receive?"
        ),

        reference=(
            "Employees receive 20 annual vacation days."
        ),

        retrieved_contexts=[
            "Employees receive 20 annual vacation days."
        ],

        response=(
            "Employees receive 20 annual vacation days."
        )
    )
]

evaluation_dataset = EvaluationDataset(
    samples=samples
)

print(evaluation_dataset)
```

### Explanation

`SingleTurnSample` represents one evaluation example.

`EvaluationDataset` contains multiple evaluation examples.

Each sample may include:

- User question
- Reference answer
- Retrieved contexts
- Generated response

### Note

The supported fields and dataset APIs depend on your installed RAGAS version. Check the official documentation if you encounter API differences.

# 12. Dataset Design for Different RAG Metrics

Different metrics require different dataset fields.

| Metric | Required Evaluation Information |
|---|---|
| Faithfulness | User input, response, retrieved contexts |
| Answer Relevancy | User input, response |
| Context Precision | User input, retrieved contexts, reference for reference-based variants |
| Context Recall | User input, retrieved contexts, reference |

This means you should create a dataset containing all relevant fields whenever possible.

## Recommended Dataset Structure

```python
sample = {
    "user_input": "What is the refund policy?",

    "reference": (
        "Customers can request refunds within 30 days."
    ),

    "retrieved_contexts": [
        "Customers can request refunds within 30 days."
    ],

    "response": (
        "Customers can request refunds within 30 days."
    )
}
```

This structure can support multiple evaluation metrics.

# 15. Common Evaluation Dataset Mistakes

## Mistake 1 — Using Generated Answers as References

Your application's generated answer should not automatically become the reference answer.

References should be independently verified.

## Mistake 2 — Creating Only Easy Questions

Easy questions may not reveal retrieval and generation problems.

## Mistake 3 — Missing Multi-Fact Questions

Multi-fact questions help test whether retrieval finds all required information.

## Mistake 4 — Ignoring Unanswerable Questions

A RAG application should know when the knowledge base does not contain an answer.

## Mistake 5 — Using Too Few Questions

A dataset with only five questions may not represent real user behavior.

## Mistake 6 — Changing the Dataset Between Comparisons

If you change the evaluation dataset every time, comparisons between application versions become unreliable.

Maintain a stable benchmark dataset.

# 16. Interview Questions and Answers

### Q1. What is a RAG evaluation dataset?

A collection of test questions, expected answers and supporting evaluation information used to measure RAG application quality.

### Q2. Why do we need an evaluation dataset?

It enables systematic evaluation, regression testing and comparison of RAG configurations.

### Q3. What is ground truth?

Ground truth is the expected correct information used as a reference during evaluation.

### Q4. What is the difference between reference and response?

Reference is the expected answer. Response is the answer generated by the application.

### Q5. Can an LLM generate evaluation questions?

Yes. An LLM can generate synthetic questions and references from documents, but they should be validated.

### Q6. What is a synthetic evaluation dataset?

An evaluation dataset generated automatically, often using an LLM.

### Q7. Why include unanswerable questions?

To test whether the RAG application avoids inventing information when evidence is unavailable.

### Q8. Should the evaluation dataset change after every prompt update?

No. Keep a stable benchmark for reliable comparisons. You can add new examples through a controlled process.

### Q9. What is regression testing in RAG?

Running a stable evaluation dataset against a new RAG version to identify quality improvements or regressions.

### Q10. Which fields should a RAG evaluation dataset contain?

At minimum, user questions and references. For comprehensive evaluation, also store retrieved contexts and generated responses.
